# Beads Board для Orca

**Ваша доска Beads — внутри Orca.** Находите готовые задачи, разбирайтесь в зависимостях и обновляйте их, не покидая рабочее пространство. Источником данных остаётся Beads: панель работает с установленным `bd` и существующим проектом.

[English](README.md)

![Доска Beads с демонстрационным проектом](docs/images/native-board-0.2.1.png)

*Доска выше снята с настоящей панели Orca 1.4.250 с синтетическими задачами. Таблица и карточка ниже — исторические браузерные снимки. Данные частных проектов не публикуются.*

## Установка стабильного выпуска

Текущий выпуск — **v0.2.4**. Установите нативный плагин напрямую из Git: сборка исходников и dev link не нужны. Передача существующей сессии отключена. Появление в каталоге сообщества — отдельный процесс, который может потребовать проверки.

В Orca откройте **Настройки → Плагины → Добавить плагин → По URL Git…** и укажите:

```text
https://github.com/Roflochinsky/beads-orca#v0.2.4
```

Другой вариант — [каталог сообщества Orca](https://onorca.dev/plugins/roflochinsky.beads?catalog=community), когда плагин в нём появится. Проверить [статус листинга](https://www.onorca.dev/plugins/roflochinsky/beads-orca) можно отдельно; установка из Git не зависит от листинга.

Требования:

- Orca версии **1.4.250 или новее**.
- Beads CLI **1.3.2** на хосте исполнения и инициализированный проект Beads.
- POSIX и `python3` для документов и артефактов; системный SSH и явная настройка для удалённых хостов.

При установке проверьте издателя и запрошенный доступ, подтвердите его только при доверии к плагину и откройте панель **Beads Board** в Orca. Локальные рабочие пространства Orca добавляются автоматически. Другие локальные проекты можно указать в настройке **Additional local Beads project paths** — по одному абсолютному пути к проекту в строке.

Выбирайте проект по workspace, хосту и полному пути в переключателе проектов. Одинаковые имена `main` или `develop` не означают одинаковую базу. `Not checked` означает, что плагин ещё не читал этот workspace. Плагин использует конфигурацию Beads выбранного workspace: не мигрирует старые базы и не подменяет их базой другого checkout.

> **Доверяйте плагину осознанно.** Это trusted worker, а не изолированная песочница. Он запускается с полным доступом вашей учётной записи и вызывает локальный `bd` для чтения и изменения задач. Устанавливайте его, только если доверяете плагину и выбранным проектам. Перед подтверждением проверьте запрошенные разрешения Orca.

## Работа с задачами (стабильный выпуск)

- **Находите следующую задачу.** Переключайтесь между доской и сортируемой таблицей, ищите по названию, ID, описанию, исполнителю или метке и фильтруйте по представлению, типу, приоритету и исполнителю.
- **Загружайте большие проекты целиком.** Ответы проходят через ограничение Orca в 1 MiB порциями, без обрезания задач. Загрузка, ошибка и устаревшие данные различаются; неудачное чтение не превращается в ложную доску с нулём задач.
- **Понимайте зависимости.** Просматривайте связи на доске и в карточке задачи; подсвечивайте блокеры и зависимые задачи. Готовность и блокировка берутся из Beads, а не из отдельного механизма правил.
- **Продвигайте работу.** Создавайте и редактируйте задачи, управляйте зависимостями и комментариями, выполняйте Claim, Close и Reopen из панели. После Close доступен защищённый Undo: он переоткрывает задачу, только если она не изменилась после закрытия.

## Новое в 0.2.4

При загрузке проектов и задач отображается skeleton выбранного представления: доски или таблицы. Фоновое обновление сохраняет уже загруженные задачи. Состояние загрузки доступно скринридерам; настройка reduced motion отключает пульсацию. Ошибки и пустые рабочие пространства не маскируются под загрузку.

## Новое в 0.2.3

В **Epics → Filters** доступны фильтры списка эпиков по статусу, приоритету и исполнителю. Поиск работает по названию и ID. Статус берётся из самого эпика в Beads, а не вычисляется по дочерним задачам.

Фильтры эпиков не меняют список задач. Выбранный эпик остаётся видимым даже вне условий фильтрации, с явным пояснением. **Reset** сбрасывает только условия списка эпиков. Они также сбрасываются при смене проекта и действуют только в текущей сессии, отдельно от сохранённых фильтров задач.

Если задачи не найдены, сообщение занимает всю область содержимого и располагается по центру. Кнопки **Reset task filters** и **Show all issues** возвращают к списку. Элементы управления адаптированы для узких панелей.

## Новое в 0.2.2

Согласованное обновление навигации и производительности:

- **Навигация по эпикам.** Раздел Epics находится под Views. Можно выбрать эпик с потомками или No epic, сохранив выбранный статус.
- **Единые представления.** Ready, In progress, Blocked, Closed и Deferred открывают таблицу. All issues запоминает Board/Table. Счётчики шапки и боковой панели используют одинаковые фильтры.
- **Создание из боковой панели.** New issue находится под проектом и остаётся видимой в узкой панели.
- **Документы внутри Orca.** Плитка Markdown открывает файл в редакторе рабочего пространства. Preview и Include — отдельные действия; Show more раскрывает остальные вложения.
- **Ограниченный DOM без обрезания данных.** Доска и таблица отображают видимое окно задач. Фильтры, сортировка и выбор используют полный набор.

Архив только плагина доступен в [релизе v0.2.2](https://github.com/Roflochinsky/beads-orca/releases/tag/v0.2.2). Предложения документов через агента в это обновление не входят. Навигация по эпикам работает без имени SSH-хоста; для сохранения переносимого фильтра имя обязательно.


## Ограничения стабильного выпуска

Плагин добавляет панель, а не заменяет Tasks Orca. Передача существующей сессии отключена до появления атомарной idle-only отправки в Orca. Передача новой сессии не выполняет Claim и не закрывает задачу автоматически. Удалённый доступ требует явного SSH-сопоставления; база Beads и целевой workspace должны находиться на одном хосте исполнения.

Конфигурация проекта и маршрутизация считаются доверенными. В Beads 1.3.2 проверка локального ID и последующая запись не атомарны: если внешний процесс удалит задачу между ними, штатная маршрутизация по префиксу может обратиться к другому настроенному хранилищу. Плагин не изолирует базы. Подробности — в [контракте адаптера](src/core/README.md).

Этот репозиторий предназначен только для Orca. Плагин для Tern находится в [beads-tern](https://github.com/Roflochinsky/beads-tern), другие хосты и исходный браузерный HUD — в [beads-hud](https://github.com/Roflochinsky/beads-hud) и его [native-интеграциях](https://github.com/Roflochinsky/beads-hud/tree/main/native).

## Сценарии версии 0.2.0

Плагин поддерживает следующие сценарии:

- **Явные поручения:** выбор задач разных проектов, группы с исходной базой и целевым workspace, предпросмотр блокеров и явно выбранного Markdown-контекста целиком или по строкам, режим реализации или исследования. Изменённый контекст отклоняет Send с пояснением и требует нового предпросмотра. Запуск новой CLI-сессии использует квитанции Orca; отправка не означает Claim, принятие или завершение работы.
- **Несколько хостов:** локальные проекты и SSH-проекты, чьё имя хоста Orca совпадает с алиасом `~/.ssh/config`, доступность хостов и offline-снимки с исходным временем получения. База Beads и целевой workspace должны находиться на одном хосте исполнения. Paired-хосты без SSH-сопоставления видимы, но не поддерживаются.
- **Контекст и проверка:** чтение/открытие Markdown, личные фильтры и явная публикация проектных, личная история с экспортом/импортом/удалением, предпросмотр/создание native worktree, отчёты по каждой задаче и явная очистка артефактов. Нет автоматических повторных отправок, Close, merge, push или удаления worktree.

**Передача существующей сессии заблокирована:** в Orca нет атомарного native idle-only gate перед отправкой. Найденные сессии недоступны для Send, чтобы не прервать текущую работу.

Для разработки нужны Orca **1.4.250+**, Node **24+** и `bd` **1.3.2** на хосте исполнения. Файловые операции требуют POSIX и `python3`; удалённый доступ — системного SSH и алиаса `~/.ssh/config` (либо перекрытия `remoteHosts`). См. [настройку и границы доверия](docs/integration-constraints.md), включая ограничение стандартного native-профиля, гонку открытия редактора и содержимое SSH config.

Для 0.2.1 прошли 78 тестов, smoke с настоящим `bd` и локальная сборка. Настоящая панель Orca на Linux загрузила 1262 задачи через native bridge без обрезания. **Работа настоящей модели, native UI Orca на macOS и реальный paired runtime не проверены.** Обнаружение провайдера не доказывает авторизацию; импортированная история и отчёты требуют человеческой проверки.

Подробнее: [контракт workflow](docs/workflow.md), [настройка и границы доверия](docs/integration-constraints.md).

[Предпросмотр поручения в native Orca](docs/images/native-handoff-unreleased.png). Настоящий снимок 1301×900 с синтетическими задачами и реализацией выпуска без тестового launch adapter; запуск агента не показан.

## Разработка

В корне репозитория, с Node.js **24 или новее** и установленным `bd` 1.3.2:

```sh
npm ci
npm run typecheck
npm run build
npm test
npm run smoke
npm run package:plugins
```

Результат сборки — `dist/orca`. Smoke использует одноразовый проект Beads и собранный worker, а не интерфейс реальной Orca. Локальные планы, обсуждения ревью и журналы приёмки исключены из Git.

Для локальной загрузки в режиме разработки проверьте запрос и выполните точную команду подтверждения, которую вернёт Orca:

```sh
orca-ide plugin validate ./dist/orca --json
orca-ide plugin dev load ./dist/orca --json
orca-ide plugin open local.beads --panel beads --json
```

В Linux вне терминала Orca используйте `orca-ide`: команда `orca` может означать системный экранный диктор. Identity `local.beads` относится к загрузке для разработки, а не к каталогу сообщества.
